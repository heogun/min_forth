# CS-DRAFT-1 최악 조건 타이밍 검토

검토일: 2026-11-24. 대상: `integrated/` 회로도·넷리스트(`integrated.net.xml`)와 현재 **임시 배치**.
`CIRCUIT.md` "아직 통과하지 않은 조건" 2–7을 데이터시트 값으로 계산했다.

**결론(2026-11-25 갱신): 회로, 배치, 클록 분포의 구조적 문제는 계산상 해소했다. 남은 것은 실측 항목(13.3절)과 기구 검토이며, 재배선을 진행할 수 있다.**
처음 계산에서 조건 2·3(Attribute SRAM 주소 경로)은 원본 Redux의 기존 최장 경로보다 길어지는 **구조적 회귀**였다.
조건 4(RAM `/CE` 디코드)도 같은 문제였으나, 2026-11-24 ATF22V10C 단일 단 디코드로 계산상 해소했다(10절).
조건 2·3의 adder 문제도 같은 날 주소 경로를 바꿔 비트맵 경로 이하로 만들었다(11절). 다만 4절의 WE OR 단 정정과 배치 조건이 남는다.
조건 6·7은 통과, 조건 5는 배치를 압축해야 통과를 판단할 수 있다.

이 문서는 계산 검토이며 실측이 아니다. 판정이 "통과"여도 오실로스코프 측정은 남는다.

## 1. 방법

### 1.1 세 가지 조건

| 열 | 의미 |
| --- | --- |
| **typ\*** | 로직은 VCC 4.5V·25°C TYP, 메모리는 **MAX**(SRAM/FLASH 데이터시트에 TYP가 없음) |
| **max25** | 모든 부품 25°C MAX |
| **max85** | 로직 −40..85°C MAX. 메모리는 사용 부품이 상업용(0..70°C)이라 같은 MAX |

- 보드 전원은 5.0V ±5%로 제한했으므로 4.5V 표 값은 보수적이다. 6V 열은 쓰지 않았다.
- 모든 로직 값은 CL = 50 pF 조건이다. 트레이스·팬아웃이 그보다 크면 지연이 더 늘어난다.
- **최소 지연**(hold 분석)은 HC 데이터시트에 없다. hold 문제는 정량 판정하지 않고 위험으로만 표시한다.

### 1.2 원본 Redux도 최대값으로는 8MHz를 닫지 못한다

원본 RAM 읽기 경로 중 최장 경로(R0)는 다음과 같다.
`CLK_REG ↑ → U24 HC161 step Q → U21 microcode FLASH(tAA) → ~RO → U34 RAM tOE → BUS`.

| | typ\* | max25 | max85 |
| --- | ---: | ---: | ---: |
| R0 도착 | 25+70+30 = **125** | 41+70+30 = **141** | 51+70+30 = **151** |
| 허용(125 − HC377 setup) | 113 | 113 | 110 |
| 여유 | −12 | −28 | −41 |

원본은 실제 부품이 데이터시트 최대값보다 빠르다는 사실에 기대어 동작한다.
따라서 이 검토는 다음 두 기준으로 판정한다.

1. **원본의 같은 경로보다 길어지지 않는가.** 이것을 주 기준으로 쓴다.
2. typ\* 조건에서 사이클 안에 들어오는가.

원본 경로보다 길어지면 원본이 가진 실제 여유를 새 회로가 소비한다는 뜻이다. 이를 "회귀"로 표시한다.

## 2. 조건 4 — 새 RAM 차단 신호와 CPU RAM 접근

### 2.1 변경점

- **원본:** U34의 `/CE`는 확장 포트 INH 하나뿐이며, R5로 GND에 내려 평소에는 정적으로 low다.
  RAM 선택은 `CE2 = A15 OR BANK7`, 즉 HC32 한 단으로 이루어진다.
- **통합안:** `/CE = CS_RAM_INH = INH_EXT | IO_HIT | ATTR_CPU`이며 주소로 디코드된다.
  최장 입력은 A8이고, 다음과 같이 6단이다.

```text
A8 → U65 HC04 → U64 HC30 → U65 HC04 → U67 HC11 → U71 HC32 → U71 HC32 → U34 /CE
```

### 2.2 읽기: 주소 변경 후 데이터 유효 시점

| 경로 | typ\* | max25 | max85 |
| --- | ---: | ---: | ---: |
| 원본 A: HC161 Q → tAA | 80 | 96 | 106 |
| 원본 B: HC161 Q → HC32 → CE2 tACE | 90 | 116 | 131 |
| 원본 R0(1.2절) | 125 | 141 | 151 |
| **신규 D: HC161 Q → 6단 → `/CE` tACE** | **137** | **212** | **252** |
| D − R0 | **+12** | **+71** | **+101** |

D는 다음 접근마다 적용된다.

1. **확장 레지스터에 접근한 직후의 다음 접근.** `/CE`가 high에서 low로 돌아와야 한다.
   예를 들어 `SDB 0xFEE2` 다음의 opcode fetch가 여기에 해당한다. Forth의 `SN!`, `ATTR!`, `COLOR`가
   매번 이 전이를 만든다.
2. **함수 해저드가 생기는 주소 전이.** MAR 출력은 동시에 바뀌지 않는다. 각 비트가
   시작값이나 끝값 중 하나로 `1111 1110 111x xxxx` 패턴을 만족하면, 중간 코드가
   순간적으로 I/O 창과 일치할 수 있다. 예를 들어 `0x7FFF → 0x8000`(MAR 증가)이 그렇다.
   그러면 `/CE`에 짧은 high 펄스가 생기고, 그 접근은 D만큼 늦어진다.
   데이터에 따라 간헐적으로 생기는 오류가 된다.

**판정: 실패(구조적 회귀).** typ\*에서도 원본 최장 경로를 12ns 넘는다.

### 2.3 쓰기

- `~WE`는 사이클 끝의 `~CLK_PLS` 펄스(8MHz↑ 직후)로 만들어진다. 주소는 사이클 시작부터 안정해 있다.
- I/O 창 쓰기는 디코드가 늦어도 RAM의 `0xFEEx`에 값이 같이 써질 뿐이라 해가 없다.
- Attribute 모드에서 `0x4000..0x7FFF` 쓰기를 차단하는 경로(`ATTR_CPU`, 3단)의 도착은
  typ\* 57, max25 101, max85 126이다. typ에서는 통과하고 max85에서는 `~WE` 펄스 시작(약 125)과 겹친다.
  차단이 늦으면 비트맵 RAM mirror가 덮어써진다. **판정: max85 경계.**
- 확장 접근 직후 일반 RAM 쓰기는 `/CE` 복귀(max85 197)가 `~WE` 펄스보다 늦어 쓰기를 잃을 수 있다.
  **판정: max 조건 실패.**

### 2.4 제어 레지스터 load enable (U69 HC173, U70 HC377)

- 두 래치의 launch(CLK_REG)와 capture(CLK_MAR)는 같은 RC 노드에서 나온다. 따라서 클록 지연은 상쇄된다.
- U70의 E는 `OR(Y0_N, ~RI)`다. `~RI`는 microcode FLASH에서 온다.

| 경로 | typ\* | max25 | max85 |
| --- | ---: | ---: | ---: |
| U70 E = HC161 → FLASH → HC32, 허용 113/113/110 | 105 (+8) | 131 (−18) | 146 (−36) |
| U69 E1 = Y2_N(HC04→HC30→HC138 G→Y), 허용 113/113/110 | 61 (+52) | 109 (+4) | ≈136 (−26) |
| 원본 RAM `~RI`→`~WE` 비교 경로 | +18 | −7 | – |

U70은 원본 비교 경로보다 약 11ns 짧은 여유를 가진다. **판정: 경계(원본보다 약간 나쁨).**

### 2.5 상태 읽기 (`0xFEE1`, U75 HCT244)

`~RO` 경로는 `HC161 → FLASH → U72 HC32 → HCT244 ten`이다.
도착은 typ\* 126(R0 대비 +1), max25 166(+25)이다.
READY를 잘못 읽으면 SN 전송이 조기에 해제된다. **판정: 경계.**

## 3. 조건 2 — Attribute SRAM 읽기와 16MHz capture

비트맵과 Attribute 경로는 같은 fetch 창(`~VGA_GET`)과 같은 16MHz edge에서 U35(HC166)와
U81(HCT377)에 load된다. U77의 `/OE`는 VRAM과 같은 `~VGA_GET`을 쓰므로 OE 경로는 동일하다.
따라서 차이만 계산한다.

| 항목 | typ\* | max25 | max85 |
| --- | ---: | ---: | ---: |
| U78 HC283(C0→C4) + U79 HC86 → CA10 | ≈28–31 | 59 | 74 |
| capture setup 차이(HC166 16/20 → HCT377 12/15) | −4 | −4 | −5 |
| **Attribute − 비트맵** | **≈+26** | **+55** | **+69** |

### 3.1 VA 버스 RC (기존 흑백 화면에도 영향)

**스캐너 HC590의 `/OE`는 GND다.** U37/U39 출력은 R9–R22(470Ω)를 거쳐 VA 버스에 늘 연결되고,
VREG(HC574)가 켜질 때 저항을 이기고 버스를 구동한다. 그래서 스캐너 주소로 돌아가는 속도는
`470Ω × VA 버스 용량`으로 정해진다.

- 통합안은 VA0–5, VA8–13에 U77, U78, U84/U85/U87 입력(각 최대 10pF)을 추가했다.
- 현재 임시 배치는 U36(VRAM)에서 U77까지 **213mm**, U78까지 **285mm**, U84까지 **336mm**다.
- 2층 FR4 0.25mm 트레이스를 약 0.45pF/cm로 잡으면, 선마다 **+20–35pF**가 늘어난다.
- 그러면 τ는 +9.4–16.5ns 늘고, 70% 정착에 +11–20ns, 90% 정착에 +22–38ns가 더 든다.

이 지연은 **원본 비트맵 fetch에도 그대로 더해진다.** 확장을 달면 흑백 화면 타이밍도 나빠진다.

원본 VGA 경로의 절대 여유는 데이터시트 값으로 닫히지 않았다. VRAM `tOE` 최대 30ns와
HC166 setup을 합치면 62.5ns 창을 넘는다. 원본도 실제 부품 속도에 기대고 있다는 뜻이다.

**판정: 고위험(구조적 회귀).** Attribute 경로는 비트맵보다 26–69ns 길다.
그와 별개로 VA 용량이 비트맵 경로까지 늦춘다.

## 4. 조건 3 — VREG 캡처, plane FF, WE 펄스

- **U82 plane FF setup:** D는 `ATTR_MODE`이고, 별도 명령으로 최소 4클록(500ns) 전에 바뀐다.
  HC74 setup 25ns 대비 충분하다. **통과.**
- **Attribute 쓰기 주소 setup:** 쓰기 주소는 VREG(U40/U41)에서 바로 나온다.
  하지만 U77에 닿으려면 adder와 XOR를 거쳐야 한다. 반면 `/ATTR_WE`는 VRAM `/WE`에 OR 한 단을 더한 것뿐이다.

| | typ\* | max25 | max85 |
| --- | ---: | ---: | ---: |
| 주소 추가 지연 − `/WE` 추가 지연 | ≈+20 | +39 | +49 |

AS6C62256은 `tAS = 0`이고 `tAW ≥ 50`이다. 원본 `/WE`는 자기 종료형 펄스로, SR latch와 NOR 3단을 거쳐 typ 약 27ns다.
따라서 Attribute 주소는 펄스 대부분 동안 아직 바뀌는 중이다. 이미 원본 펄스부터 `tWP = 45`에 못 미친다.
**판정: 고위험(실패 가능성 높음).** 데이터가 다른 Attribute 행에 쓰일 수 있다.

- **비트맵/Attribute WE 비중첩:** `BITMAP_WE_N = WE_RAW | PENDING_ATTR`, `ATTR_WE_N = WE_RAW | PENDING_BITMAP`이다.
  Q와 Q̄가 바뀌는 시점은 VREG_CP뿐이다. VREG_CP는 8MHz↑에서 약 28ns(typ) 뒤에 오고,
  쓰기 창은 CLK_MAR↑ 경로를 따라 약 21ns(typ) 뒤에 닫힌다. 그래서 겹치지 않을 여유가 약 7ns(typ)밖에 없다.
  이 경쟁은 원본에도 있다. 하지만 CLK_MAR에 부하가 늘면(5절) 여유가 더 줄어든다. **판정: 경계(원본 승계).**

## 5. 조건 5 — 클록 부하

| 클록 | 추가 부하 | 임시 배치 거리 |
| --- | --- | --- |
| 16MHz(X1) | U81 CP, U83 CP | X1→U81 124mm, X1→U83 197mm |
| CLK_MAR(U6 HC02) | U69 CP, U70 CP | U6→U69 84mm, U6→U70 119mm |

- HC 출력 지연은 부하 1pF당 약 0.08ns(typ)~0.17ns(max) 늘어난다. HC161·HC574의 50pF와 150pF 값 차이에서 구했다.
- CLK_MAR에 트레이스와 입력으로 약 +15–30pF가 붙으면 +1–5ns 늦어진다.
  같은 노드에서 나오는 CLK_REG는 그대로이므로, 이만큼 클록 skew가 생긴다.
  - MAR 쪽 hold 여유가 그만큼 줄어든다.
  - 4절의 7ns 경쟁 여유도 줄어든다.
  - HC 최소 지연이 공개되지 않아 hold를 정량 판정할 수는 없다.
- X1 발진기의 허용 부하(15pF급인지 50pF급인지)는 BOM에 부품번호가 없어 확인하지 못했다.
  16MHz 트레이스가 200mm 이상이면 15pF급 발진기의 정격을 넘을 수 있다.

**판정: 위험.** 배치를 압축하거나 클록을 버퍼링한 뒤 다시 계산해야 한다.

## 6. 조건 6 — pixel → mux → DAC, blanking 정렬

세 경로 모두 같은 16MHz edge(U35, U81, U83)에서 출발한다.

| 경로 | typ\* | max25 | max85 |
| --- | ---: | ---: | ---: |
| pixel(컬러): HC166 → U88 S→Y → U89 B→Y → AC244 | 51 | 87 | 128.5 |
| attr: HCT377 → U88 → U89 → AC244 | ≈47 | 95 | 131.5 |
| 흑백 bypass: HC166 → U89 A→Y → AC244 | 33 | 62 | 90.5 |
| blank: HC173 → HC86 → AC244 OE | 34.5 | 69 | 84.5 |

- pixel과 Attribute의 skew는 −4/+8/+3ns다. 16MHz 1픽셀(62.5ns)의 1/8 이하다.
- blanking은 pixel보다 16–44ns(≤0.7픽셀) 먼저 바뀐다. 활성 영역 첫·끝 픽셀의 가장자리만 영향을 받는다.
- 원본(R6 직결)보다 화면 전체가 sync 기준으로 최대 약 1.3픽셀 오른쪽으로 밀린다. 균일한 이동이므로 모니터가 흡수한다.

**판정: 통과.** 가장자리 fringe는 실측으로 확인한다.

## 10. 수정 반영 1 — ATF22V10C 단일 단 디코드 (2026-11-24)

| --- | ---: | ---: | ---: | --- |

  - PLD 입력 18개가 주소 버스에 부하를 더한다. 현재 임시 배치에서 주소선은 약 330mm다. 이 부하는 배치를 압축(8절 3번)한 뒤 다시 계산한다.
  - ICC 최대 130mA가 늘어난다.
  - 상태 읽기 경로는 그대로이므로 펌웨어 보완(8절 5번)은 여전히 유효하다.

## 11. 수정 반영 2 — Attribute 주소를 VA 버스 앞에서 계산 (2026-11-24)

8절 2번을 반영했다. 회로 설명은 `CIRCUIT.md` "최소 구성으로 바꾼 부분"과 "Attribute 갱신"에 있다.

| 경로 | 변경 전 | 변경 후 |
| --- | --- | --- |
| 표시 행 주소 | VA 버스(470Ω RC) → HC283 → HC86 → U77 | 카운터 출력(RCLK, 이전 fetch 끝) → HC283 → HC86 → 470Ω → `CS_CA` → U77 |
| CPU 쓰기 행 주소 | VREG U41 → VA → HC283 → HC86 → U77 | U66 HC574(U41과 같은 CP·OE) → `CS_CA` → U77 |
| 표시 영역 판정 | VA2–VA5, `CS_CA7..10` | 카운터 출력 `CS_H2..H32`, `CS_SCA7..10` |
| 확장 회로의 VA 부하 | VA0–5: U77, 창 판정 게이트. VA8–13: U78/U79 | VA0–5: U77만. VA6–13: 없음 |

### 11.1 표시(읽기)

- **행 주소 정착:** 카운터 레지스터는 직전 fetch 끝(`~VGA_GET`↑)에 갱신된다.
  adder와 XOR 출력은 그 뒤 HC590 RCLK→Q + HC283 C0→C4 + HC86 = 46 / 90 / 116ns 안에 정착한다.
  다음 fetch까지는 약 375ns가 남으므로 이 경로는 임계 경로가 아니다.
- **VREG 구간 뒤 복귀:** fetch 직전에는 U66이 비활성화된다. 그 뒤 `CS_CA`는 470Ω을 거쳐 스캐너 값으로 돌아간다.
  이것은 비트맵 VA의 복귀와 같은 구조다.
  - τ = 470Ω × C_CA. C_CA는 U77 입력, U66 출력, 짧은 트레이스로 이루어진다.
  - 행 주소 비트(`CS_CA`)는 VA 비트보다 부하가 작으므로, 같은 거리에 배치하면 VA와 같거나 더 빨리 정착한다.
- **판정:** Attribute 데이터 도착 시점은 비트맵과 같은 열 주소(VA0–5) 경로와 같은 `~VGA_GET` OE 경로로 정해진다.
  capture setup은 4–5ns 덜 필요하다. **비트맵 경로 이하(회귀 해소). 조건: U77·U66·R37–R41을 VRAM 근처에 배치.**
- **비트맵 쪽 개선:** VA6–VA13은 원래 부하로 돌아갔고, VA0–5에는 입력 하나(U77)만 더해졌다. 3.1절의 VA 용량 회귀는 열 비트로 줄었고, 그 크기는 배치 거리에 비례한다.

### 11.2 CPU 쓰기

- **행 주소:** U66은 U41과 같은 부품, 같은 `CS_VREG_CP`, 같은 `~VREG_OE`를 쓴다. 따라서 행 주소는 VREG 열 주소와 **같은 시점**(tEN 26/30/38)에 유효해진다. adder 지연은 없다.
- **D setup:** CPU 주소 A9–A13은 사이클 시작부터 안정해 있고 VREG_CP는 사이클 끝에 온다. 그래서 U41과 같은 여유가 있다.
- **판정:** 쓰기 주소 setup은 비트맵과 같다. **회귀 해소.**
- **4절 정정:** 4절은 "`/ATTR_WE`는 VRAM `/WE`에 OR 한 단을 더한 것"이라고 비교했다.
  하지만 통합안에서는 VRAM `/WE`(`CS_BITMAP_WE_N`)도 U71 OR를 지난다. 두 plane끼리의 WE 차이는 0이다.
  원본 Redux와 비교하면 두 plane 모두 `/WE` 양쪽 edge가 10/20/25ns 늦다. setup 쪽은 그만큼 나아지고,
  **쓰기 종료 후 주소 hold(tWR = 0)는 그만큼 나빠진다.** 이것은 이번 수정과 별개로 남은 항목이다.
  U71을 74AC32로 바꾸면 추가 지연이 약 1/3로 준다. 이 안은 측정 후 판단한다.

### 11.3 대가와 검증

- **부품 추가:** U66 HC574 1개, C36, R37–R41(470Ω 5개). 확장 부품은 68개, IC는 24개다.
- **소프트웨어 계약 변경:** CPU는 cell의 아래 네 줄(`0x440c + row·512 + col`)에 써야 한다.
  minforth `ATTR!`/`ATTRFILL`과 `minredux-cs` 모델을 함께 바꿨다. 이 계약을 지키지 않으면 쓰기가 한 행 위로 간다.
- **검증:**
  - KiCad ERC 0건, physical DRC 0건, parity 0건. 미배선은 384건이다.
  - 하드웨어 테스트 33개가 통과했다(1 skip). 주요 확인 항목은 다음과 같다.
    - 전체 raster에서 스캔 행이 +4 위상과 같고, 표시 창 판정이 맞다.
    - U66의 핀, 클록, OE가 U41과 같다.
    - VA6–VA13에 확장 부하가 없다.
    - 1,500개 cell 전부 쓰기 주소가 맞다.
  - `minredux-cs`: Rust 65 + 4 통과, ext_regress 7/7, Forth/ABORT/P2 회귀 통과.
  - 실측은 하지 않았다.

## 12. 수정 반영 3 — 배치 압축 (2026-11-25)

8절 3번을 반영했다. 새 부품은 이제 원래 보드 **위쪽 가장자리 위에 붙인 띠**에 들어간다.
J4(DSUB)는 위쪽 가장자리를 향하므로, x 29–64mm 구간은 비워 플러그 자리를 남겼다(L자 외형).

- **배치 방법:** 각 부품의 기준 x는 연결된 core pad x의 평균이다. 가중치는 1/fanout을 줘서 버스가 기준을 끌어당기지 않게 했다.
  셀(IC + 바이패스 C + 그 IC와 가장 많이 연결된 수동소자)을 타이밍 우선순위대로 행에 배치한다.
  - 우선순위: VA/CA, 16MHz, RAM `/CE`, WE → CLK_MAR 래치·팔레트 → 상태·음원.
  - 각 셀은 기준 x에 가장 가까운 빈 구간을 고르며, core에서 한 행 멀어질 때마다 60mm 비용을 준다.
  - 결과는 결정적이다. 두 번 실행해도 같다.
- **크기:** 띠 높이 111.9mm, 보드 232 × 270mm, 약 58,700mm². 이전 shelf 배치는 422 × 158mm, 약 66,600mm²였다.
- **검증:**
  - KiCad ERC 0건, physical DRC 0건(courtyard 겹침 포함), parity 0건. 미배선은 384건이다.
  - `route_board.py prepare`가 L자 외형 전체로 GND zone을 만들고 DSN을 내보냈다.
  - 하드웨어 테스트 34개 통과(1 skip). 띠·notch 불변식 테스트를 추가했다.

### 12.2 3.1·5절 추정값 갱신

- **VA0–VA5:** U77까지의 추가 트레이스가 약 61mm다. 0.45pF/cm이면 약 2.7pF이고, U77 입력(≤10pF)을 더하면 선마다 **+5–13pF**다.
  이전 추정은 +20–35pF였다. τ는 +2.4–6.1ns, 90% 정착은 **+5.5–14ns**로 줄었다(이전 +22–38ns).
  VA6–13에는 확장 부하가 없다(11절).
- **`CS_CA`:** U66, U77, R37–R41이 같은 영역에 있다. 그래서 11.1절의 "같은 거리 배치" 조건을 충족한다. 최종 배선 후 길이를 확인한다.
- **CLK_MAR:** U69/U70까지 76–110mm다. 트레이스와 입력 두 개로 약 +10–25pF가 붙고, CLK_REG 대비 skew는 +1–4ns로 추정한다(이전 +1–5ns).

  X1 정격 부하는 여전히 확인하지 못했다. **8절 4번의 16MHz 버퍼는 계속 필요하다.**
- **아직 남은 것:**
  - 클록 버퍼링(8절 4번)
  - WE 경로 OR 단의 hold 측정(11.2절)
  - 상태 읽기 경로(2.5절)
  - 새 외형의 기구 검토: 모서리 장착 구멍, 케이스
  - 실제 배선 후 길이 재계산

## 13. 수정 반영 4 — 클록 분리 (2026-11-25)

8절 4번을 반영했다. 회로는 `CIRCUIT.md` "클록 분리"에 있다. 추가 부품은 U67(74HC02), U68(74AC08), R42(33Ω), R43(0Ω trim)과 바이패스 C37·C38이다.

### 13.1 16MHz

- **X1 부하:** 확장 회로가 X1 넷에 더하던 부하가 약 +15–29pF(U81, U83 입력과 137+53mm 트레이스)였다.
  지금은 AC08 입력과 68mm 스텁으로 **약 +7.5pF**다. X1 정격은 여전히 모르지만 부하는 원본에 가까워졌다.
- **확장 클록 지연:** AC08 tpd에 R42(33Ω)와 부하(U81·U83 ≤20pF, 트레이스 약 4pF)의 RC 약 0.5–0.8ns를 더하면
  **≈ 2 / 6 / 8.3 / 9.3ns**(min / typ / max25 / max85)다.
- **hold:** U81(HCT377)의 E hold는 5ns, D hold는 3ns다. U83(HC173)의 E hold는 0ns, D hold는 3ns다.
  따라서 `~VGA_GET`(U19 HC161 CLK→Q + U4 HC00)이 core edge 뒤 **≥ 14.3ns**까지 바뀌지 않아야 한다.
  typ은 25 + 9 = 34ns로 2.4배 여유가 있다. HC 최소 지연은 공개되지 않아 **실측 항목**으로 남긴다.
- **setup:** 확장 클록이 늦는 만큼 U81/U83의 setup 여유는 2–9ns 늘어난다.
- **6절 정렬 갱신:** attr − pixel skew는 +2 / +16.3 / +12.3ns로, 1픽셀(62.5ns)의 1/4 이하다.
  blanking이 pixel보다 먼저 바뀌는 정도는 10.5 / 9.7 / 34.7ns다. **통과 유지.**
- **신호 품질:** AC 출력의 2–3ns edge로 53–92mm 트레이스를 구동하므로 R42로 직렬 종단했다. 값은 실측으로 조정한다.

### 13.2 CLK_MAR

- **core CLK_MAR 부하는 원본과 똑같다.** 5절에서 걱정한 MAR 쪽 skew(+1–5ns)는 사라졌다.
- **RC 노드 영향:** C33 노드에 HC 입력 1개(3.5–10pF)와 40mm 스텁(약 1.8pF)이 붙는다.
  - 노드 용량은 29–42pF에서 34–54pF가 되고, τ(R26 150Ω)는 4.4–6.3ns에서 5.2–8.1ns가 된다.
  - 그래서 CLK_MAR와 CLK_REG가 8MHz 대비 **함께 +0.8–1.8ns** 늦어진다. 둘 사이의 관계는 유지된다.
  - C32 노드(`~CLK_PLS`)도 R25를 거쳐 비슷하게 따라간다. core 쪽 변화는 이것뿐이다.
- **U67 복제 클록의 skew:** core CLK_MAR 부하는 HC161 6개, U7, J3, 긴 트레이스로 약 35–80pF다.
  U67 부하는 U69, U70, 256mm 트레이스로 약 18–31pF다.
  0.08–0.17ns/pF로 환산하면 U67이 **1.4–8.3ns 먼저** 바뀐다.
  - hold: U69/U70이 버스와 `~RI` 변화보다 먼저 capture하므로 **안전한 방향**이다.
  - setup: 그만큼 준다. U70 E(PLD 경로)의 여유는 typ +2.2..+9.1ns, max25 −6.9..−13.8ns다.
    max 조건에서는 원본 `~RI`→`~WE` 경로(−7ns)와 비슷하거나 약간 나쁘다.
  - R43에 47–150Ω을 넣으면 확장 부하와의 RC로 약 1–3ns를 늦출 수 있다. 실측한 skew로 값을 정한다.

### 13.3 실측 항목 (재배선 후 시제품)

1. 16MHz 기준 `~VGA_GET` 최소 지연(≥14.3ns 필요)과 X1 파형
2. CLK_MAR와 `CS_EXT_CLK_MAR`의 skew → R43 값 결정
3. C33/C32 노드 파형과 `~WE` 펄스(RC 노드 부하 +5–12pF의 영향)
4. 11.2절 WE 경로 OR 단의 hold(tWR = 0)
5. 2.5절 상태 읽기 경로

검증: KiCad ERC 0건, physical DRC 0건, parity 0건, 미배선 410건. 하드웨어 테스트 35개 통과(1 skip).
`route_board.py prepare`도 정상 종료했다. 새 테스트는 CLK_MAR와 16MHz의 core 넷 구성원과 확장 클록 구동 구조를 고정한다.
